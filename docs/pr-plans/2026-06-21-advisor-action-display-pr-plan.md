## 1. 本计划解决什么

这个计划把已确认的“投资助手展示窗口”拆成可以逐个开发、逐个验收的 PR。

页面的核心目标不是让用户在网页里反复操作，而是让系统像投资助手一样告诉用户：

- 已经买入的股票：现在应该持有、观察、减仓还是退出。
- 如果要卖：什么价格、什么条件、什么原因。
- 还没买的股票：什么条件出现才值得准备买入。
- 暂时不该买什么：为什么不买。
- 下一步系统正在看护什么：卖出线、买入触发线、板块退潮、复盘到期。
- Codex 可以在页面之外做什么：记录成交、加入观察池、设置提醒、写回外部验证结果。

后台需要做复杂的数据沉淀和规则计算，但页面只呈现结果、原因和少量关键图形。

## 2. 全局原则

- 不使用或要求 `OPENAI_API_KEY`。
- 不自动实盘交易，不保存券商或聚宽密码。
- Codex 是主要指令入口，Web 页面是结构化展示窗口。
- 页面使用中文，先做桌面端，不做手机端适配。
- 页面不提供聚宽、回测任务、券商或下单操作入口。
- 每条建议都必须有原因、风险和数据新鲜度。
- 买入事实、卖出事实、外部验证结果和复盘结论都必须保留历史记录。
- “建议买入”必须表达为候选计划和触发条件，不能表达为确定性收益承诺。

## 3. 每个 PR 的统一验收门槛

每个 PR 完成后都必须满足：

- 做一次代码 review，优先检查风险、回归、缺失测试和安全边界。
- 有当前 PR 的验收用例。
- 有整体功能回归用例。
- 后端改动至少通过 `.venv/bin/python -m compileall -q agent`。
- 前端改动至少通过 `npm --prefix frontend run build`。
- 涉及页面的 PR 要做浏览器真实页面验证。
- 不能引入 API key、明文密码、自动实盘下单能力。
- 文档要同步说明新能力如何通过 Codex 使用。

## 4. 推荐交付节奏

建议分成 14 个 PR：

- PR-A0 到 PR-A8：建立“行动建议”的数据、规则和统一 API。
- PR-A9：实现用户真正看到的 4 个桌面展示页面。
- PR-A10 到 PR-A12：补齐 Codex 指令、提醒、复盘和外部验证结果写回。
- PR-A13：做完整发布验收。

前 10 个 PR 做完后，系统就能形成核心可用版本：用户可以告诉 Codex 自己买了什么，系统能在页面上展示下一步行动建议。

  - `/advisor/today`
  - `/advisor/holdings`
  - `/advisor/watchlist`

  - 今日建议。
  - 我的持仓。
  - 观察清单。
  - 复盘记录。
- 明确桌面端优先，手机端暂不做。
- 明确页面不承载复杂表单编辑。
- 明确页面不承载聚宽或回测任务入口。

验收：

- 页面结构和 Figma V4 一致。
- 说明 Web 页面是展示层，Codex 是指令入口。

测试：

- 文档检查。
- 不产生运行时代码变更。

## PR-A1：投资助手数据模型

目标：让系统具备记录持仓、候选、策略逻辑、行动建议和历史快照的基础数据结构。

范围：

- 新增或迁移以下核心表：
  - `portfolios`：组合基础信息。
  - `position_lots`：买入批次和成本。
  - `investment_theses`：买入或观察逻辑。
  - `watchlist_items`：观察清单。
  - `advisor_action_recommendations`：行动建议记录。
  - `advisor_action_snapshots`：助手展示快照。
  - `advisor_command_events`：Codex 指令事件记录。
  - `external_validation_results`：Codex 写回的外部验证结果。
- 字段必须覆盖：
  - 股票代码、股票名称、板块、策略周期、买入价、数量、成本、持有状态。
  - 卖出线、买入触发线、不买条件、最大仓位、复盘日期。
  - 证据链接、数据日期、数据新鲜度、建议生成时间、外部验证摘要。
- 保留与现有事件、板块、策略和历史验证结果的关联字段。

验收：

- 可以创建一个组合、一个持仓批次、一个观察项和一条建议记录。
- 建议记录能追溯到来源证据。
- 外部验证结果可以写入，但不会变成页面操作入口。
- 数据结构不依赖任何 OpenAI API key。

测试：

- 数据迁移测试。
- 数据模型字段校验测试。
- 后端编译检查。

## PR-A2：Codex 持仓与成交记录 API

目标：让用户通过 Codex 说“我买了/卖了什么”，系统能把它记录成结构化持仓。

范围：

- 新增本地 API：
  - `POST /api/advisor/transactions`：记录买入、卖出、调仓、费用。
  - `GET /api/advisor/portfolio-summary`：读取组合、持仓、成本和盈亏摘要。
  - `GET /api/advisor/positions`：读取当前持仓明细。
- 支持幂等字段，避免 Codex 重试时重复写入。
- 支持手工录入的成交，不连接券商，不下单。
- 卖出记录要能回写到持仓批次，保留已清仓历史。

验收：

- 用户说“我以 10.20 买入 300 股某股票”，Codex 能调用 API 记录。
- 页面或 API 能看到该股票当前持仓成本。
- 卖出后能区分部分卖出和全部清仓。

测试：

- 买入记录测试。
- 部分卖出和清仓测试。
- 重复请求幂等测试。
- 不存在交易执行接口的安全测试。

## PR-A3：投资逻辑与持有周期模型

目标：让系统不是只看涨跌，而是围绕“为什么买、什么情况说明错了、持有多久”来判断。

范围：

- 为持仓和观察项绑定 `investment_theses`。
- 支持策略类型：
  - 长期质量趋势。
  - 中期景气趋势。
  - 短期热点趋势。
  - 事件驱动观察。
  - 回测候选策略。
- 每个逻辑必须有：
  - 买入或观察原因。
  - 入场条件。
  - 退出条件。
  - 不买条件。
  - 最大仓位。
  - 预期持有周期。
  - 复盘频率。
- 没有投资逻辑的持仓要标记为“逻辑不完整”。

验收：

- 每个持仓能看到对应投资逻辑。
- 没有退出条件的策略不能进入“可买入”状态。
- 持有周期能影响后续建议口径。

测试：

- 投资逻辑创建和更新测试。
- 缺少退出条件的校验测试。
- 持仓与投资逻辑关联测试。

## PR-A4：行情与数据新鲜度解析

目标：让建议知道当前价格、历史价格和数据是否过期。

范围：

- 复用现有 `market_daily`、`sector_daily`、异动快照和采集结果。
- 新增价格解析服务：
  - 查询持仓股票最新可用价格。
  - 查询观察股票最新可用价格。
  - 标记停牌、缺数据、非交易日、数据过期。
- 每个价格输出必须带：
  - 数据日期。
  - 来源。
  - 是否最新。
  - 如果不是最新，说明原因。

验收：

- 交易日有数据时显示最新价格。
- 周末或节假日显示“非交易日/使用最近交易日数据”。
- 缺数据不会导致建议页面崩溃。

测试：

- 正常行情测试。
- 非交易日测试。
- 缺数据降级测试。
- 后端编译检查。

## PR-A5：已买股票诊断与卖出线引擎

目标：为已经买入的股票生成“下一步怎么做”和“什么条件卖出”。

范围：

- 新增持仓诊断服务，输出动作：
  - 继续持有。
  - 观察。
  - 减仓。
  - 退出。
  - 补充投资逻辑。
- 每个动作必须有：
  - 建议动作。
  - 触发价格或触发条件。
  - 原因。
  - 风险。
  - 下一次复盘时间。
- 卖出线可以来自：
  - 硬止损价。
  - 跌破关键均线或趋势位。
  - 投资逻辑失效。
  - 板块热度退潮。
  - 持有周期到期复盘。
- 输出必须标注为研究建议，不是交易指令。

验收：

- 已持仓股票能显示“现在动作”和“卖出线”。
- 缺少投资逻辑时，不给出具体卖出价，只提示补充逻辑。
- 卖出原因不能只写“下跌”，必须关联策略逻辑或风险条件。

测试：

- 持有建议测试。
- 触发减仓或退出测试。
- 缺少投资逻辑测试。
- 数据过期时的谨慎输出测试。

## PR-A6：候选股票与买入触发线引擎

目标：把热点、板块、事件和策略卡转成“准备观察、什么条件才买”的候选清单。

范围：

- 候选来源包括：
  - 热点事件。
  - 板块热度。
  - 用户让 Codex 加入的股票。
  - 策略卡。
  - 外部验证后待观察策略。
- 每个候选输出：
  - 建议状态：观察、等待买点、可小仓试探、风险过高、已错过。
  - 买入触发价或触发条件。
  - 不买条件。
  - 最大仓位。
  - 预期持有周期。
  - 主要证据。
- 候选股票不能直接等同于买入清单。

验收：

- 页面能显示“准备买入观察清单”。
- 每个候选都有买入条件和不买条件。
- 没有退出条件的候选不能进入“可小仓试探”。

测试：

- 事件生成候选测试。
- 板块热度生成候选测试。
- 缺少买入触发条件的校验测试。
- 候选状态流转测试。

## PR-A7：暂时不买与风险过滤器

目标：让助手明确告诉用户“哪些东西现在不要买”，帮助避免冲动追高。

范围：

- 新增风险过滤规则：
  - 已连续大涨但没有回撤保护。
  - 没有清晰卖出线。
  - 证据不足，只有市场传闻。
  - 板块拥挤或情绪过热。
  - 与当前持仓高度重叠。
  - 回测不足或回测质量差。
  - 流动性、ST、停牌、退市等风险。
- 输出“暂时不买清单”，并给出一句话原因。
- 风险过滤结果要影响 PR-A6 的候选状态。

验收：

- 系统能明确列出不该买的类型或股票。
- 每条不买理由都能追溯到规则或证据。
- 不买清单不会被误展示成负面投资结论，只表达当前阶段风险。

测试：

- 追高风险测试。
- 无卖出线风险测试。
- 证据不足测试。
- 持仓重叠风险测试。

## PR-A8：投资助手展示快照 API

目标：提供 4 个展示页专用 API，让前端读取结构化结果，不在页面拼复杂后台逻辑。

范围：

- 新增：
  - `GET /api/advisor/today-snapshot`
  - `GET /api/advisor/holdings-snapshot`
  - `GET /api/advisor/watchlist-snapshot`
  - `GET /api/advisor/journal-snapshot`
- 输入：
  - `portfolio_id`
  - `as_of_date`
- 今日建议输出：
  - 今日结论。
  - 市场状态摘要。
  - 已买股票行动建议。
  - 准备买入观察清单。
  - 暂时不买清单。
  - 三条以内核心原因。
  - 数据新鲜度和缺失说明。
  - 证据链接。
- 我的持仓输出：
  - 组合概况。
  - 持仓动作。
  - 卖出线或复盘线。
  - 持仓逻辑健康度。
  - 集中风险。
- 观察清单输出：
  - 等待买点。
  - 继续观察。
  - 暂时不买。
  - 机会来源。
  - 触发条件地图。
- 复盘记录输出：
  - 决策时间线。
  - 策略有效性。
  - 错误模式。
  - 本周复盘重点。
  - 经验库。
- 快照可以按日保存，支持历史回看。

验收：

- 前端不需要调用多个底层接口拼页面。
- 无持仓时仍能显示候选和风险提示。
- 数据不足时页面能给出“无法判断”的原因。

测试：

- 快照正常返回测试。
- 空持仓测试。
- 缺数据测试。
- 历史日期查询测试。

## PR-A10：Codex 指令助手与 MCP 工具

目标：让用户主要通过 Codex 口头或文字指令推进系统状态。

范围：

- 新增或扩展 Codex 可调用工具：
  - 记录买入。
- 记录卖出。
- 加入观察池。
- 设置买入触发线。
- 设置卖出提醒线。
- 写入外部验证结果。

- 工具输出要适合 Codex 直接解释给用户。

验收：

- 用户可以对 Codex 说“我今天买入了 X”，系统页面更新。
- 用户可以让 Codex 写回外部验证结果，页面只更新状态和复盘，不出现回测入口。

测试：

## PR-A11：提醒与复盘记录

目标：让助手不仅展示今天，还能持续跟踪买入、卖出和观察的后续变化。

范围：

- 新增或扩展提醒：
  - 触及卖出线。
  - 接近买入触发线。
  - 投资逻辑失效。
  - 板块热度退潮。
  - 持仓集中度过高。
  - 复盘日期到期。
- 新增或扩展决策日志：
  - 用户接受或拒绝建议。
  - Codex 当时的解释。
  - 后续结果和复盘结论。
- 提醒和日志要能被 PR-A8 快照读取。

验收：

- 触发条件出现时能生成提醒。
- 用户接受或拒绝建议后有历史记录。
- 页面能显示最重要的提醒，不把明细堆满。

测试：

- 提醒触发测试。
- 提醒确认和关闭测试。
- 决策日志写入测试。
- 快照读取提醒测试。

## PR-A12：外部验证结果写回

目标：让 Codex 把外部回测、模拟或人工验证结果写回本地系统，作为策略证据和复盘材料。

范围：

- 新增或扩展外部验证结果写入能力。
- 支持结果来源：
  - Codex 在外部平台完成的回测。
  - 用户手工告诉 Codex 的验证结果。
  - 公开数据环境产生的模拟结果。
- 支持写入验证摘要：
  - 收益。
  - 回撤。
  - 胜率。
  - 交易次数。
  - 交易成本。
  - 是否通过当前策略筛选门槛。
  - 失败原因或降级原因。
- 验证结果影响观察状态、不买理由、策略有效性和复盘记录。
- 页面只展示结果摘要，不提供发起回测入口。

验收：

- 可以通过 Codex 写入一条外部验证结果。
- 写入后，候选状态、复盘记录和今日建议能更新。
- 页面没有聚宽或回测任务按钮。
- 不允许自动实盘下单。

测试：

- 外部验证结果写入测试。
- 候选状态更新测试。
- 复盘记录联动测试。
- 无页面回测入口安全测试。

## PR-A13：完整发布验收

目标：把行动建议页作为一个可发布能力整体验收。

范围：

- 完整流程：
  - 记录一笔买入。
  - 补充投资逻辑。
  - 生成已买股票卖出线。
  - 加入一个候选股票。
  - 生成买入触发条件。
  - 标记一个暂时不买风险。

  - 页面刷新后展示最新行动建议。
