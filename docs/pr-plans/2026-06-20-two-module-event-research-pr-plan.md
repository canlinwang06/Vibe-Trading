# 双模块事件研究改造 PR 计划

日期：2026-06-20
对应设计文档：`docs/superpowers/specs/2026-06-20-two-module-event-research-design.md`
Figma：<https://www.figma.com/design/CkTWDFwz0lG4vtck4g4w1A?node-id=5-2>

## 总体建设策略

本次改造分为 9 个 PR。每个 PR 都必须做到：

- 只解决一个清晰目标。
- 提供代码 review。
- 提供当前 PR 修改点验收用例。
- 提供整体功能不回退的验收用例。
- 自动测试通过。
- 本地 VS Code 可编译。

## PR-00：产品设计与 PR 拆解

目标：沉淀双模块产品设计和后续 PR 计划。

范围：

- 新增产品设计文档。
- 新增 PR 拆解文档。
- 不修改运行时代码。

验收：

- 文档说明事件记录库和板块及股票分析的职责边界。
- 文档包含 Figma 链接、数据流、验收标准和 PR 列表。

测试：

- 文档路径存在。
- Git diff 只包含文档变更。

## PR-01：导航与路由信息架构调整

目标：把原分散页面的信息架构收敛为两个主入口。

范围：

- 新增 `/event-records` 路由：事件记录库。
- 新增 `/sector-stock-analysis` 路由：板块及股票分析。
- 更新侧边栏中文导航。
- 原事件雷达、板块雷达、事件反应、候选股票池路由暂时保留为兼容入口或内部入口。

验收：

- 侧边栏显示事件记录库和板块及股票分析。
- 两个新路由可打开。
- 旧路由不出现空白页。

测试：

- 更新导航配置单元测试。
- 新增两个页面的 smoke test。
- `npm --prefix frontend run build` 通过。

## PR-02：事件记录库数据模型与 API 整理

目标：为客观事件记录和事后影响沉淀建立清晰后端边界。

范围：

- 梳理现有事件表、原文表、事件映射表。
- 增加或封装事件记录库查询 API。
- 明确 source_url 和 local_document_ref 的输出。
- 预留 impact_t1、impact_t5、impact_t20、impact_t60 字段。

验收：

- API 能返回事件列表、证据入口、涉及板块/个股。
- 事件字段区分发布时间、可知时间和可交易时间。
- 无真实链接时能返回本地原文引用。

测试：

- 后端 API 单元测试。
- `.venv/bin/python -m compileall -q agent` 通过。

## PR-03：事件记录库页面

目标：实现事件记录库第一版页面。

范围：

- 页面总览卡片。
- 事件记录列表。
- 原文/本地原文入口展示。
- 影响跟踪摘要区。
- 历史归档入口。

验收：

- 用户可以看到 AI 算力样例事件。
- 页面文案明确说明“客观记录，不直接给买入建议”。
- 事件列表能展示来源、摘要、涉及板块/个股。

测试：

- 前端页面测试。
- 空数据、加载失败、正常数据三种状态测试。
- `npm --prefix frontend run build` 通过。

## PR-04：事件后影响跟踪

目标：沉淀事件发生后对板块和个股的真实影响。

范围：

- 增加影响快照计算或读取能力。
- 支持 T+1、T+5、T+20、T+60。
- 区分板块影响和个股影响。
- 在事件记录库中展示影响跟踪结果。

验收：

- 每条事件能看到后续板块影响。
- 每条事件能看到后续个股影响。
- 未到观察窗口时显示等待状态，而不是错误。

测试：

- 影响窗口计算测试。
- 无行情数据时的降级测试。
- 后端 compileall 和前端 build 通过。

## PR-05：板块热度评分

目标：为板块及股票分析提供可解释的热点板块排行。

范围：

- 定义板块热度评分模型。
- 输入包含近期事件密度、历史反应、板块走势、个股映射。
- 输出板块排行和评分解释。
- 提供周期参数：近 7 日、近 30 日、本季度、今年。

验收：

- 能看到 AI 算力、光模块、服务器、数据中心等板块排行。
- 每个板块有热度分数和原因说明。
- 分数来源可解释，不只是黑盒数字。

测试：

- 评分模型单元测试。
- 周期切换测试。
- 后端 compileall 通过。

## PR-06：板块及股票分析页面

目标：实现板块及股票分析第一版页面。

范围：

- 当前结论卡片。
- 热点板块排行。
- 热度来源解释。
- 板块 x 股票矩阵。
- 周期复盘视图。

验收：

- 页面能回答“当前哪些板块比较热”。
- 页面能解释“为什么这个板块热”。
- 周期切换不会导致页面状态混乱。

测试：

- 页面正常数据测试。
- 周期切换测试。
- 空数据和异常状态测试。
- `npm --prefix frontend run build` 通过。

## PR-07：分层候选股票池

目标：把候选股票从单一列表升级为分层来源。

范围：

- 候选股票增加来源分类。
- 支持事件直接影响、板块热度带动、事件与板块共振、用户自选补充。
- 在板块及股票分析中展示候选股票理由。
- 支持生成观察池。

验收：

- 候选股票不再只有名字和分数。
- 每只股票有来源分类和入池理由。
- 用户能保存观察池，供策略实验室使用。

测试：

- 候选池生成测试。
- 候选分类测试。
- 用户加入/排除测试。

## PR-08：策略实验室与聚宽导出衔接

目标：让板块及股票分析产出的观察池能进入策略实验室并导出聚宽草稿。

范围：

- 策略实验室支持读取观察池。
- 聚宽导出展示策略草稿。
- 复制按钮支持一键复制聚宽策略代码。
- 页面强调回测在聚宽执行，本系统不默认回测。

验收：

- 用户能从候选池进入策略实验室。
- 用户能生成聚宽策略草稿。
- 用户能一键复制到聚宽。

测试：

- 策略草稿生成测试。
- 聚宽导出页面测试。
- 复制按钮测试。

## PR-09：端到端验收与文档更新

目标：完成完整功能测试和使用说明。

范围：

- 更新 README 或项目使用文档。
- 增加从事件记录到板块分析再到聚宽导出的完整流程说明。
- 浏览器真实模拟测试。
- 补充回归测试。

验收：

- 用户能按文档完成 AI 算力研究流程。
- 页面无“等待某 PR 完成”的占位文案。
- 所有核心功能可通过浏览器真实模拟。

测试：

- 前端 build。
- 后端 compileall。
- 核心页面测试。
- 浏览器端到端模拟测试。

## 推荐执行顺序

1. PR-00 产品设计与 PR 拆解
2. PR-01 导航与路由信息架构调整
3. PR-02 事件记录库数据模型与 API 整理
4. PR-03 事件记录库页面
5. PR-04 事件后影响跟踪
6. PR-05 板块热度评分
7. PR-06 板块及股票分析页面
8. PR-07 分层候选股票池
9. PR-08 策略实验室与聚宽导出衔接
10. PR-09 端到端验收与文档更新

## 每个 PR 的固定交付物

- 代码实现或文档变更。
- 代码 review 结论。
- 当前 PR 验收用例。
- 整体功能回归用例。
- 自动测试执行结果。
- 本地编译结果。
