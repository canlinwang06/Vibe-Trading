## 总体定位

后续改造以“Codex 指挥、系统呈现、聚宽验证”为主线。

用户主要通过 Codex / Cortex 发出自然语言指令。Vibe-Trading 本地系统负责保存数据、暴露结构化 API、展示图形化看板和记录任务证据。聚宽负责回测和模拟盘验证。Web 页面不再承担大量手工参数录入，而是呈现市场情报、候选策略、聚宽任务状态和策略生命周期。

## 设计原则

- Codex 是主要操作入口：选择策略、触发聚宽回测、读取聚宽结果、写回本地系统。
- Web 是图形化呈现层：少参数、多图表、多结论、多状态留痕。
- 本地系统不保存聚宽账号密码，不绕过验证码，不自动实盘下单。
- 聚宽自动化优先使用用户已登录浏览器会话或聚宽研究环境脚本。
- 所有自动化动作必须有任务记录、错误状态、结果摘要和证据。
- 手工复制、下载和导入保留为失败兜底。
- 每个 PR 都要提供代码 review、当前 PR 验收用例和核心流程 smoke test。

## 页面目标

主页面收敛为：

- 每日市场情报：看今天市场发生了什么，哪些数据源成功，哪些板块和个股异动。
- 事件记录库：看客观事件、来源可信度、原始链接和事件后影响。
- 板块及股票分析：看热点板块、候选股票、候选策略生成入口。
- 策略生命周期：看策略从 idea 到 paper_trading / rejected 的晋级状态。
- 聚宽任务中心：看 Codex 发起的聚宽回测/模拟任务状态和结果写回。

## PR-07：可信互联网数据源注册

目标：建立可信互联网数据源框架，支持官方、行情、财经媒体和社交线索分层。

范围：

- 扩展 `source_registry` 初始化数据。
- 注册巨潮、交易所、证监会、东方财富、AKShare、腾讯行情等来源。
- 为每个来源声明可信等级、用途、采集方式、是否需要人工核验。
- 前端数据源页面展示来源状态和可信等级。

验收：

- 能看到官方、行情、媒体、社交线索四类来源。
- 未验证社交线索不能进入策略证据。
- 无需 OpenAI API Key。

测试：

- 后端 source registry 初始化测试。
- 前端数据源页面 smoke test。
- `.venv/bin/python -m compileall -q agent`
- `npm --prefix frontend run build`

## PR-12：候选策略工厂升级

目标：从热点事件、板块和候选股票自动生成多类型候选策略卡。

范围：

- 扩展策略卡字段：假设、证据、适用场景、入场/退出、仓位、风险、聚宽任务入口。
- 生成热点动量、事件驱动、龙头确认、补涨扩散、回调再启动、低波核心、过热规避、组合策略。
- 策略卡保持 research_only，不直接生成实盘指令。

验收：

- 同一主题能生成多张不同类型策略卡。
- 每张策略卡有证据、风险和可测试规则。
- 策略卡可进入聚宽任务中心。

测试：

- 策略生成 API 测试。
- 策略卡前端展示测试。
- 保存策略卡到策略库测试。

## PR-13：Codex 聚宽任务编排 API

目标：让 Codex 能读取策略任务包，并记录送往聚宽的任务状态。

范围：

- 新增 `jq_orchestration_tasks`。
- 新增任务 API：创建任务、读取任务包、更新状态、记录错误、写入证据。
- 任务包包含策略代码、参数、回测区间、风险提示、source_strategy_id。
- 任务状态支持 draft / waiting_confirm / running / completed / failed / cancelled。

验收：

- Codex 可通过 API 获取完整聚宽任务包。
- 任务状态可被 Codex 更新。
- 自动化失败有错误原因和兜底建议。

测试：

- 任务创建和状态迁移测试。
- 任务包字段完整性测试。
- 权限和 research_only 边界测试。

## PR-15：聚宽结果自动写回

目标：把聚宽回测/模拟结果写回本地系统。

范围：

- 新增聚宽结果写回 API。
- 支持回测指标：收益、年化、最大回撤、Sharpe、胜率、交易次数、基准对比。
- 支持交易明细和截图证据。
- 将结果绑定到 `strategy_id`、`idea_id`、`jq_task_id`。

验收：

- 聚宽结果写回后，策略状态能更新为 backtested。
- 页面能展示回测摘要和基准对比。
- 原始结果和证据可追溯。

测试：

- 结果解析测试。
- 写回幂等测试。
- 异常字段和缺失字段测试。

## PR-16：策略生命周期看板

目标：展示策略从候选到模拟盘观察的完整生命周期。

范围：

- 新增 `strategy_lifecycle` 和 `strategy_lifecycle_events`。
- 新增策略漏斗、健康分、运行天数、信号数、回测次数、状态时间线。

验收：

- 用户能看到所有策略处于哪个阶段。
- 策略晋级/暂停/淘汰都有原因和证据。
- 页面以图形化漏斗、趋势和评分为主。

测试：

- 生命周期状态迁移测试。
- 健康分计算测试。
- 页面图表和空状态测试。
