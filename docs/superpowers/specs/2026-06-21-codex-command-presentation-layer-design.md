# Codex 指挥型呈现层产品设计

日期：2026-06-21
状态：已生成 Figma 示例稿并完成首轮代码落地

Figma：<https://www.figma.com/design/uJIRmpirtD8JIeQb1oGzYg>

## 一句话定义

本系统的主交互入口是 Codex / Cortex，自然语言指令负责策略选择、聚宽调度和结果写回；Web 系统主要负责把数据、状态、证据和策略生命周期以图形化方式呈现出来。

## 为什么调整

用户不希望在系统页面里手工配置大量参数，也不希望自己频繁复制代码、切换聚宽、导入结果。用户希望通过 Codex 发话，由 Codex 协调本地系统和聚宽。

因此页面设计要从“操作表单”转向“研究看板”：

- 看今天市场发生了什么。
- 看系统生成了哪些候选策略。
- 看哪些策略已经送到聚宽回测。
- 看聚宽结果是否已经写回。
- 看策略是否应该继续观察、暂停或淘汰。

## 系统角色

### Codex / Cortex

- 理解用户自然语言指令。
- 调用本地 API 读取候选策略和任务包。
- 在用户授权的浏览器会话中操作聚宽回测或模拟准备。
- 读取聚宽结果、截图留证、写回本地系统。
- 给用户解释下一步可以怎么做。

### Vibe-Trading 本地系统

- 保存可信数据源、事件、行情、板块、候选股票、策略卡、聚宽任务和生命周期状态。
- 提供结构化 API 给 Codex 调度。
- 展示图形化看板。
- 保留手工兜底入口。

### 聚宽

- 执行回测和模拟盘验证。
- 输出回测指标、交易明细和模拟结果。
- 不由本地系统保存账号密码。
- 不允许自动实盘下单。

## 页面信息架构

### 每日市场情报

回答：今天市场发生了什么？

展示：

- 市场温度计。
- 指数和成交概览。
- 板块热力图。
- 涨停、炸板、跌停、异动股票趋势。
- 今日关键事件时间线。
- 数据源新鲜度。

主操作：

- 让 Codex 生成今日候选策略。
- 查看数据缺失原因。

### 事件记录库

回答：事实是什么，证据在哪里？

展示：

- 今日事件摘要。
- 来源可信等级。
- 官方、媒体、社交线索分层。
- 原文链接。
- 事件影响板块和个股。
- T+1 / T+5 / T+20 影响跟踪。

主操作：

- 让 Codex 基于某个事件生成候选策略。
- 查看原始证据。

### 板块及股票分析

回答：哪些板块和股票值得观察？

展示：

- 热点板块排行。
- 板块热度趋势。
- 市场确认度。
- 龙头、补涨、低波核心、过热风险分布。
- 候选股票评分矩阵。
- 候选策略卡入口。

主操作：

- 让 Codex 基于当前板块生成候选策略。
- 把选中的策略送入聚宽任务中心。

### 策略生命周期

回答：策略现在处于什么阶段？

展示：

- 策略漏斗：idea → candidate → backtested → qualified → paper_trading → paused / rejected。
- 策略健康分。
- 运行天数、信号次数、回测次数。
- 收益、回撤、胜率、盈亏比、交易成本。
- 状态变化时间线。

主操作：

- 让 Codex 筛选可继续观察的策略。
- 让 Codex 暂停或淘汰不合格策略。
- 让 Codex 生成下一轮聚宽回测任务。

### 聚宽任务中心

回答：Codex 发给聚宽的任务到哪一步了？

展示：

- 待确认任务。
- 运行中任务。
- 已完成任务。
- 失败任务。
- 聚宽回测指标摘要。
- 任务时间线。
- 截图证据。
- 写回状态。

主操作：

- 让 Codex 继续执行当前任务。
- 查看失败原因。
- 使用手工复制/导入兜底。

## 页面设计原则

- 首屏先给结论和状态，不先给参数。
- 图表优先，明细表放到下钻区。
- 大段代码、JSON、CSV 不作为主视图。
- 筛选项保持轻量：日期、主题、策略状态、风险等级。
- 重要动作以 Codex 指令为主，页面只保留确认、查看和兜底。
- 所有建议都必须显示原因、风险和证据。

## 数据流

```text
可信互联网数据
  -> 本地事件/行情/板块/股票库
  -> 候选股票池
  -> 候选策略卡
  -> Codex 创建聚宽任务
  -> 聚宽回测/模拟
  -> Codex 读取结果
  -> 本地写回
  -> 策略生命周期看板
```

## 安全边界

- 不使用或要求 `OPENAI_API_KEY`。
- 不保存聚宽账号密码。
- 不绕过验证码或登录限制。
- 不自动实盘下单。
- 回测和模拟动作必须在用户授权范围内执行。
- 自动化失败时必须降级为手工复制、下载或导入。

## 验收标准

- 页面能以图形化方式呈现市场、事件、策略、聚宽任务和生命周期状态。
- 用户可以主要通过 Codex 指令推进流程。
- 聚宽任务有 task_id、状态、错误、结果摘要和证据。
- 策略晋级、暂停、淘汰都有理由和证据。
- 每个 PR 必须包含代码 review、自动测试和当前 PR 验收用例。
