# A 股事件研究双模块产品设计

日期：2026-06-20
状态：已基于 Figma 双模块稿确认
Figma：<https://www.figma.com/design/CkTWDFwz0lG4vtck4g4w1A?node-id=5-2>

## 一句话定义

把原来的事件雷达、板块雷达、事件反应、候选股票池重构为两个职责清晰的模块：

1. 事件记录库：客观记录事件、来源和事后影响，形成长期可复盘的事件样本库。
2. 板块及股票分析：基于事件记录库沉淀的数据，分析当前热点板块，并给出建议观察股票。

系统仍然只服务研究、模拟和聚宽回测/模拟运行，不做自动实盘交易。

## 背景和问题

当前功能分散在多个页面，用户需要在事件雷达、板块雷达、事件反应和候选股票池之间来回切换，才能拼出一条完整判断链。这个结构容易造成两个问题：

- 事件记录和投资判断混在一起，用户难以区分事实和建议。
- 候选股票来源不清楚，既可能来自事件直接影响，也可能来自板块热度扩散。

新的设计把系统拆成事实层和分析层。事实层长期沉淀可验证样本，分析层基于样本回答当前机会在哪里。

## 产品原则

- 客观记录和分析判断分离。
- 每条事件必须能追溯到原文链接或本地原文。
- 每条事件必须保留事件后影响表现，至少支持 T+1、T+5、T+20、T+60。
- 板块和股票分析必须说明推荐依据，不能只给名单。
- 候选股票必须标明来源类型：事件直接影响、板块热度带动、两者共振。
- AI 可以辅助摘要、归类、映射、排序和解释，但不直接给自动买卖指令。
- 聚宽仍然是回测和模拟运行平台，本系统负责研究和策略草稿生成。

## 导航设计

建议将 A 股研究相关主导航收敛为：

- A 股驾驶舱
- 事件记录库
- 板块及股票分析
- 策略实验室
- 交易计划
- 聚宽导出
- 每日工作流
- 数据源设置
- 系统设置

原事件雷达、板块雷达、事件反应、候选股票池不再作为同级主页面暴露。它们的能力沉入两个新模块。

## 模块一：事件记录库

### 目标

事件记录库只回答三个问题：

- 发生了什么？
- 证据在哪里？
- 事件发生后，板块和个股实际有什么表现？

它不回答“现在买什么”。

### 核心页面内容

- 今日事件记录总览：事件数量、原文证据数量、影响跟踪周期、沉淀样本数量。
- 事件记录列表：日期、事件类型、标题、摘要、来源、涉及板块/个股、原文入口。
- 影响跟踪：记录事件后 T+1、T+5、T+20、T+60 的板块和个股表现。
- 历史归档：按日、周、月、季度、年查看事件密度和影响结果。
- 客观记录字段：展示系统用于后续分析的标准字段。

### 关键数据字段

- event_id
- event_time
- publish_time
- crawl_time
- knowable_time
- tradable_time
- source_name
- source_url
- local_document_ref
- event_title
- event_summary
- event_type
- event_subtype
- related_sectors
- related_stocks
- impact_t1
- impact_t5
- impact_t20
- impact_t60
- evidence_status

### 用户流程

1. 用户或每日工作流导入事件来源。
2. 系统抽取事件摘要和结构化字段。
3. 用户检查事件摘要和原文证据。
4. 系统将事件写入事件记录库。
5. 后续交易日系统补充板块和个股表现。
6. 事件样本成为板块及股票分析的输入。

## 模块二：板块及股票分析

### 目标

板块及股票分析回答两个问题：

- 当前哪些板块比较热？
- 在这些板块里，哪些股票值得进入观察池？

它使用事件记录库沉淀的数据，不直接替代聚宽回测和人工确认。

### 核心页面内容

- 当前结论：用一句话说明当前热点和建议观察方向。
- 热点板块排行：展示板块热度评分、趋势和原因。
- 热度来源解释：拆分近期事件、历史反应、板块走势、个股映射等贡献。
- 建议观察股票：展示候选股票、代码、分数和推荐理由。
- 板块 x 股票矩阵：展示股票和板块之间的映射关系。
- 周期复盘视图：支持近 7 日、近 30 日、本季度、今年等周期切换。
- 操作入口：生成观察池、进入策略实验室、导出聚宽策略草稿。

### 候选股票来源分类

- 事件直接影响：由具体事件直接映射到个股。
- 板块热度带动：个股未必被单条事件直接点名，但所属板块热度上升。
- 事件与板块共振：既有事件映射，又处于高热度板块。
- 用户自选补充：用户手动加入观察的股票。

### 建议评分维度

- 近期事件密度
- 历史同类事件反应
- 板块热度趋势
- 股票和板块相关度
- 股票和事件相关度
- 流动性和交易约束
- 风险提示

### 用户流程

1. 用户打开板块及股票分析。
2. 选择主题和周期，例如 AI 算力、近 30 日。
3. 系统读取事件记录库和历史影响数据。
4. 系统计算热点板块排行。
5. 系统生成分层候选股票。
6. 用户保存观察池或进入策略实验室。
7. 用户在策略实验室生成聚宽策略草稿。
8. 用户复制到聚宽做回测或模拟运行。

## 数据流

```text
信息源/本地文档
  -> 事件抽取
  -> 事件记录库
  -> 事件后影响跟踪
  -> 历史事件样本
  -> 板块热度评分
  -> 股票候选评分
  -> 观察池
  -> 策略实验室
  -> 聚宽导出
```

## 技术边界

- 不要求新增 OpenAI API Key。
- 不在前端、文档、截图或日志中保存密钥。
- 不启用实盘交易。
- 首阶段可以复用现有事件、映射、候选池和聚宽导出能力。
- 新页面应优先复用现有 Tailwind、深色主题、卡片、表格和按钮样式。

## 验收标准

- 主导航中能看到事件记录库和板块及股票分析。
- 事件记录库能展示事件、原文证据和影响跟踪。
- 板块及股票分析能展示热点板块、热度解释、候选股票和来源分类。
- 候选股票能区分事件直接影响、板块热度带动、事件与板块共振。
- 每个 PR 都必须包含代码 review、当前 PR 修改点验收用例和自动测试。
- 前端变更必须通过 `npm --prefix frontend run build`。
- 后端变更至少通过 `.venv/bin/python -m compileall -q agent`。
