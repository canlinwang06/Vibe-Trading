# Personal Investment Assistant V4 Design

日期：2026-06-21
状态：设计评审稿
Figma：<https://www.figma.com/design/GbkIPNO3aPz5P79Uzr0L1y>

## 1. 一句话定义

Vibe-Trading 的下一版 Web UI 应该是一个“个人投资助手展示窗口”。

它不是交易终端，不是回测平台，也不是参数配置后台。它要像一个贴身投资助手一样，持续分析公开市场数据、用户持仓、观察清单、策略逻辑、风险信号和历史复盘结果，然后用最少的信息告诉用户：

- 今天整体应该怎么做。
- 当前持仓哪些要继续持有、减仓、退出或补充逻辑。
- 哪些股票只值得观察，什么条件出现后才考虑。
- 哪些行为今天不要做。
- 为什么系统给出这些建议。
- 接下来 Codex 应该继续看护什么。

## 2. 关键方向调整

本次设计相较上一版有三个重要变化。

第一，页面不再保留聚宽或回测操作入口。

回测可以仍然存在于工作流里，但它不应该成为页面主功能。更合适的方式是：用户让 Codex 去外部平台或公开数据环境里做验证，Codex 再把结果告诉本地系统，本地系统把结果沉淀为策略证据、观察状态或复盘记录。

第二，页面从“策略工具”转为“投资助手”。

用户不需要在页面上大量点选、筛选、配置参数。页面主要负责展示结论、理由、风险和看护状态。复杂操作交给 Codex 通过自然语言指令完成。

第三，系统核心从“生成策略”进一步变成“看护决策”。

生成股票池和策略只是中间过程。用户最终关心的是：我现在持有什么、该不该动、哪里有风险、哪里可以等机会、过去的判断是否有效。

## 3. 目标用户与使用方式

目标用户是一个使用 Codex Pro 的个人 A 股投资者。

典型使用方式：

1. 用户每天打开页面，只看结论和提醒。
2. 页面展示投资助手已经检查过的内容。
3. 用户通过 Codex 说自然语言指令，例如：
   - “我今天买入了持仓A，价格 10.20，300 股。”
   - “把 AI 算力观察清单重新评估一下。”
   - “这个策略我外部回测完了，结果是最大回撤偏高，先降级观察。”
   - “帮我看下哪些持仓需要设置卖出线。”
4. Codex 调用本地 API 更新数据。
5. 页面刷新后显示新的看护结果。

用户不需要在页面上完成复杂操作。

## 4. 信息架构

左侧菜单保留 4 个页面：

- 今日建议
- 我的持仓
- 观察清单
- 复盘记录

这四页形成一个完整闭环：

```text
今日建议 -> 告诉用户今天整体怎么做
我的持仓 -> 看护已经买入的股票
观察清单 -> 跟踪尚未买入的机会
复盘记录 -> 沉淀过去决策和经验
```

不单独设置“聚宽导出”“回测任务”主入口。外部回测结果属于后台证据和复盘材料，只在必要时作为状态或结果摘要出现。

## 5. 页面一：今日建议

### 5.1 页面目标

回答用户最核心的问题：今天我应该怎么做？

### 5.2 页面内容

页面顶部是一句助手结论，例如：

> 今天不追高，先看护持仓；AI 算力保持观察，等待更清晰买点。

核心模块：

- 市场状态：震荡偏强、震荡偏弱、风险偏高、机会偏少等。
- 仓位建议：例如 40%-55%，只作为研究纪律提醒。
- 已买股票摘要：哪些继续持有，哪些需要复盘。
- 准备买入摘要：哪些只等触发条件。
- 今天不要做：不追连续大涨、不买没有卖出线的票、不凭单条消息交易。
- 为什么这样建议：最多 3 条简短原因。
- 我正在替你看护：卖出线提醒、买入触发线、板块退潮、复盘到期。

### 5.3 页面规则

- 首屏只放结论，不放参数表。
- “买入”必须表达为“等待触发条件”，不能表达为确定性推荐。
- 风险提示必须比机会提示更醒目。
- 数据过期时必须显示“数据更新时间”和“不确定性”。

## 6. 页面二：我的持仓

### 6.1 页面目标

回答：我现在持有什么？每个持仓下一步怎么处理？

### 6.2 页面内容

顶部展示组合概况：

- 组合状态。
- 当前仓位。
- 今日需处理事项。
- 板块或主题集中风险。

持仓卡片展示：

- 股票示例名和代码。
- 当前动作：继续持有、观察、减仓、退出、补充逻辑。
- 成本和当前价格。
- 卖出线或复盘线。
- 买入逻辑是否仍成立。
- 一句话原因。
- 下一次复盘时间。

右侧展示：

- 持仓板块分布。
- 策略周期分布：短期、中期、长期。
- 投资逻辑健康度。
- 今天最需要看护的风险。

底部展示下一次看护计划：

- 明日检查卖出线。
- 本周复盘重点板块仓位。
- 本月整理策略表现。
- 触发条件到达时提醒。

### 6.3 页面规则

- 这页不提供买入、卖出按钮。
- 已持仓股票如果没有投资逻辑，状态必须显示“逻辑不完整”。
- 没有退出条件时，不能给出具体持有建议，只能提示补充策略逻辑。
- 所有价格都是研究看护信息，不是交易指令。

## 7. 页面三：观察清单

### 7.1 页面目标

回答：有哪些机会值得继续看？什么条件出现后才考虑？

### 7.2 页面内容

页面分成三类：

- 等待买点。
- 继续观察。
- 暂时不买。

候选卡片展示：

- 观察对象。
- 主题或板块标签。
- 进入观察原因。
- 买入触发条件。
- 最大仓位上限。
- 不买条件。
- 下一次检查日期。
- 热度或确认度趋势。

右侧展示：

- 机会来源：热点事件、板块强度、持仓联动、用户指定、历史复盘。
- 触发条件地图：回踩确认、放量突破、板块扩散、风险下降、逻辑补齐。
- 我正在等待什么：用三句话解释当前最重要的等待条件。

### 7.3 页面规则

- 页面必须明显标注“观察不等于买入”。
- 观察项必须有不买条件。
- 没有退出线的候选不能进入“可准备”状态。
- “暂时不买”不是负面结论，只表示当前阶段风险不合适。

## 8. 页面四：复盘记录

### 8.1 页面目标

回答：过去的投资决策哪些有效，哪些错误要避免？

### 8.2 页面内容

顶部给出复盘总结，例如：

> 最近有效的是：有卖出线的中期趋势策略；最近容易出错的是：热点退潮后继续加仓。

核心模块：

- 决策时间线：买入、卖出、放弃、观察、复盘。
- 策略有效性：中期质量趋势、短期热点趋势、事件驱动观察等。
- 错误模式：追高、无卖出线、板块过度集中、凭单条消息交易。
- 本周要复盘：持仓、观察项、卖出线完整性、仓位上限。
- 经验库：先定退出线、观察不等于买入、回测结果只是证据之一、热点退潮先降风险。

### 8.3 页面规则

- 复盘重点是决策质量，不是炫耀收益。
- 外部回测结果可以作为证据写入，但不作为页面操作入口。
- 每条复盘记录要区分事实、当时判断、用户决策和后续结果。
- 复盘输出要反向影响观察清单和今日建议。

## 9. 后台能力映射

页面虽然简单，后台需要保留足够强的数据结构。

### 9.1 数据采集

系统继续采集公开市场、新闻、事件、板块、个股、异动和历史数据。

输出给页面的是摘要结论，不是原始明细。

### 9.2 投资逻辑

每个持仓和观察项都应该有投资逻辑：

- 为什么买或观察。
- 什么情况说明判断错了。
- 什么时候复盘。
- 什么情况下退出。
- 最大仓位是多少。

### 9.3 行动建议引擎

行动建议引擎输出三类结果：

- 已买股票怎么处理。
- 未买股票等什么条件。
- 当前哪些行为不要做。

### 9.4 外部验证结果

系统不需要在页面上发起回测。

但系统要支持 Codex 写入外部验证结果，例如：

- 策略样本区间。
- 收益和回撤。
- 胜率和交易次数。
- 是否通过筛选。
- 失败原因。

这些结果进入复盘记录和策略证据，不在页面上作为主操作按钮出现。

## 10. Codex 指令边界

Codex 可以做：

- 更新持仓。
- 记录买入或卖出事实。
- 添加观察项。
- 补充投资逻辑。
- 写入外部回测或模拟结果。
- 生成复盘记录。
- 要求系统重新生成今日建议。

Codex 不应该做：

- 自动实盘下单。
- 绕过聚宽或其他平台登录限制。
- 保存任何账号密码。
- 把回测排名直接当成实盘买入依据。

## 11. 视觉设计原则

整体风格：

- 深色专业界面。
- 温和、克制、像投资助手，不像交易终端。
- 页面中文为主。
- 只做桌面端。

颜色：

- 背景：深炭黑。
- 卡片：深灰黑。
- 文本：近白色和灰色层级。
- 强调色：绿色代表逻辑成立或风险可控，琥珀色代表观察和等待，红色代表风险或退出。
- 避免大面积紫色、蓝紫渐变、米色和装饰性光斑。

布局：

- 左侧窄导航。
- 右侧主内容。
- 卡片圆角不超过 8px。
- 不做嵌套卡片。
- 不使用密集表格作为主视图。
- 图表只表达关键判断，不展示复杂指标堆叠。

文案：

- 像助手说话，但保持专业。
- 每条建议最多一到两句原因。
- 明确标注“研究建议非交易指令”。
- 不使用“稳赚”“确定上涨”“立即买入”等表达。

## 12. 空状态与异常状态

### 12.1 没有持仓

我的持仓页显示：

- 当前没有记录持仓。
- 可以让 Codex 记录当前持仓。
- 今日建议只展示市场状态和观察清单。

### 12.2 没有观察项

观察清单页显示：

- 暂无观察项。
- 系统会基于热点、板块和用户指定主题生成候选。
- 提醒用户“没有机会也是一种结论”。

### 12.3 数据过期

任何页面如果数据过期，必须显示：

- 最近数据日期。
- 过期原因。
- 当前建议可信度下降。

### 12.4 投资逻辑缺失

如果持仓或观察项缺少投资逻辑：

- 不给出强建议。
- 显示“逻辑不完整”。
- 提示需要补充买入原因、退出条件和复盘周期。

## 13. 验收标准

设计验收：

- Figma 中有 4 个桌面页面。
- 页面菜单为：今日建议、我的持仓、观察清单、复盘记录。
- 页面不出现聚宽、回测任务、券商、下单等操作入口。
- 页面表达的是看护、建议、观察和复盘，而不是交易执行。
- 每页都能在 30 秒内让用户理解核心结论。
- 每页都有数据更新时间或研究边界提示。

开发验收：

- 前端新增页面后，`npm --prefix frontend run build` 通过。
- 后端新增能力后，`.venv/bin/python -m compileall -q agent` 通过。
- 每个 PR 都有代码 review、当前 PR 验收用例、整体回归用例和自动测试。
- 页面真实浏览器检查通过。

## 14. PR 提案刷新结论

原 PR-A 计划需要刷新。

保留：

- 持仓数据模型。
- 投资逻辑模型。
- 行情和数据新鲜度解析。
- 已买股票诊断和卖出线。
- 候选股票和买入触发线。
- 暂时不买风险过滤。
- 行动建议快照 API。
- Codex 指令写入。
- 提醒和复盘记录。

调整：

- 页面从单页 `/advisor` 扩展为 4 页：`/advisor/today`、`/advisor/holdings`、`/advisor/watchlist`、`/advisor/journal`。
- 移除页面内聚宽任务入口。
- “聚宽回测任务与结果写回”改为“外部验证结果写回”，它只接收 Codex 带回的结果，不在页面发起。
- PR-A9 应从“一个桌面页面”改为“4 页展示层”。
- 复盘记录要前置，不应等到最后才做，因为它是助手长期变聪明的基础。

建议下一步：

1. 先确认这份设计文档和 Figma 四页。
